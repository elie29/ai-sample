# Accessibility audit skill

1. **Audit** (broad): keyboard navigation, focus management, accessible names,
   contrast, forms and error announcement, headings and landmarks, tables, media.
2. **Prioritize**: findings by severity, with the affected user group
   (keyboard-only, screen reader, low vision...).
3. **Ask**: the human decides what is fixed now, later, or accepted. Record it.
4. **Fix** (narrow): one finding, one component when possible, with a test.
5. **Re-audit**: verify the fix on the running application, not only in code.

A fix that has not been verified is not a fix. It is a claim.
